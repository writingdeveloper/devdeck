# 재부팅 후 세션 복원과 일괄 복원의 메모리 비용

## 확인 및 개선

| 항목 | 확인한 원인 | 처리 |
| --- | --- | --- |
| 재부팅 후 세션이 돌아오지 않음 | 자동 복원은 업데이트 재시작에만 있었다. 일반 실행에서는 열려 있던 타일이 모두 「이전 세션」으로만 남았다 | 업데이트 재시작이 아닌 실행에서는 이 PC에서 열려 있던 타일을 다시 연다. 대화 기록이 48시간 안에 쓰인 것만 열고, 고정한 세션은 항상 연다 |
| 「모두 복원」이 며칠 쉰 대화까지 다시 실행 | 위 문제 때문에 사용자가 「모두 복원」을 눌렀다. 2026-10-12 SIHYEONG-4080에서 8개를 복원했고 그중 2개는 4~5일 쓰지 않은 대화였다. 세션 하나가 약 2.4 GB(Claude + MCP 묶음)를 차지했다 | 실행 시 자동 복원이 최근 대화만 열기 때문에 「모두 복원」을 누를 일이 줄어든다. 「모두 복원」과 업데이트 재시작은 사용자가 직접 요청한 것이라 지금처럼 전부 연다 |
| 쉬는 타일도 활동 중으로 기록됨 | `lastActiveMs`는 터미널의 마지막 출력 시각이라 화면을 다시 그릴 때마다 바뀐다. 실측 결과, 63시간 쓰지 않은 대화 2개도 저장 시점 1시간 안에 활동한 것으로 기록돼 있었다 | 판단 기준을 대화 기록 파일의 수정 시각으로 바꿨다(Claude jsonl, Codex rollout). 새 IPC `cockpit:conversationsLastUsed`가 이를 일괄로 조회한다 |
| 다른 PC가 보던 세션 | 뷰어가 호스트 재부팅을 감지하면 호스트의 세션을 「이전 세션」으로 내렸고, 되살리는 일은 뷰어의 「모두 복원」에 맡겨져 있었다 | 각 PC가 실행할 때 자기 세션을 복원하고, 뷰어는 그 PC가 알려 오는 세션을 기존 방식대로 받아들인다. 뷰어는 다른 PC의 타일을 실행 시 자동으로 열지 않는다 |

`wasLive` 표시는 실행할 때 한 번 읽고 바로 지운다. 이번 실행에서 남긴 항목이 다음 실행에서 저절로 돌아오지 않게 하기 위해서다.

## QA

- 단위 검사 1,267개 통과, 기존 1개 생략. `partitionLaunchRestore`, `takeLaunchRestoreCandidates`, `cockpit:conversationsLastUsed`에 대한 검사를 추가했다.
- Electron 실행 검사: 임시 프로필에 열려 있던 타일 2개(대화 5분 전·4일 전, 둘 다 `lastActiveMs`는 1분 전)와 이전 세션 1개를 넣었다.
  - 첫 실행: 최근 타일 1개만 다시 열렸다(`launch restore reopen=1 left=1`). 나머지는 표시 없이 저장됐다.
  - 두 번째 실행: 같은 타일만 다시 열렸고(`reopen=1 left=0`), 4일 된 타일은 돌아오지 않았다.
- 실제 SIHYEONG-4080 상태로 모의 계산: 열려 있던 13개 중 10개를 다시 열고, 63시간 쓰지 않은 2개와 끝난 Codex 1개는 남긴다.

## 구분해야 하는 제한

- 48시간은 대화 기록 기준이다. 대화 없이 터미널만 열어 둔 세션은 사용 시각을 알 수 없어 남긴다. Antigravity는 대화별 기록이 없어 타일의 마지막 활동 시각을 쓴다.
- 이 기능은 세션을 실행하는 PC에 이 버전이 설치돼야 동작한다. 뷰어만 업데이트하면 호스트의 세션은 지금처럼 「이전 세션」에 남는다.
- 자동 복원된 세션도 하나하나가 에이전트 프로세스다. 쓰지 않는 세션은 닫아야 메모리가 회수된다.

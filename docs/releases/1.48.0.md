# DevDeck 1.48.0

## Lighter at rest

Measured on Windows 11 with two sessions open and nothing happening (DevDeck 1.47.0, 15 minutes): about 5% of one core — main 1.7%, renderer 2.3%, GPU 1% — and some 590 MB of working set across the five processes. Most of the CPU went to periodic work that re-read what the window was already showing. This release keeps each of those for the moments it can matter; nothing shown changes.

- **A quiet terminal is not re-scanned every second.** The activity tick reads the last 12 rows of every live terminal's buffer once a second to tell working from waiting. A terminal that was not written to since the last tick still shows what it showed then, so the scan is skipped — it runs after each write, and for two more seconds while xterm catches up with it.
- **The process listing that detects a tile's agent runs only after that tile printed something.** Every 30 s each tile asked main which agent runs under its shell; main answered off a listing of every process on the machine — a PowerShell process on Windows, about 500 ms and 80 MB each time, cached 15 s. A tile that printed nothing cannot have changed agent. The listing still runs on selecting a tile, on the update restart, and whenever a tile has output.
- **Git is re-read every two minutes for tiles you are not looking at.** Every 30 s each tile ran `git rev-parse` and `git status` (and more for a workspace) for the branch and dirty count in its row. The selected tile keeps its 30 s; the other rows refresh every fourth tick, and nothing is re-read while the window is hidden. Selecting a tile refreshes it at once, as before.
- **The background-session listing slows down when there is nothing to watch.** `claude agents --json --all` starts a Claude Code process (~340 ms) every 30 s, on this PC and on every connected one. It stays at 30 s while the window is focused and the group has rows; a minute when the group is empty everywhere (a new `claude --bg` still shows within a minute); two minutes while the window is not focused.

With two idle sessions this removes two git processes and one PowerShell process per 30 s, two Claude Code processes per minute, and about two terminal-buffer scans per second — the scheduled process starts at rest drop from roughly 9 per minute to 1.

## What was looked at and left alone

- The 250 ms spinner tick already pauses when the window is unfocused or hidden, and does nothing when no row is working.
- The 5 s image poll reads only the selected Claude session, and costs one `stat` while it is idle.
- The 15 s projects re-scan runs only while the projects view is active and the window focused.
- The session-meta read (model, active time, context) folds only the lines appended since the last read; the usage footer polls every 5 minutes; the link heartbeat is one small frame per 15 s per machine.
- Memory: the renderer's share is mostly the terminals' 10,000-line scrollbacks and xterm's DOM rows; the GPU process (~135 MB) is Chromium's compositor and does not grow with sessions.

# DevDeck 1.40.0

## Which step was this screenshot?

- **Image rows in the terminal.** Where Claude Code printed `[Image]` (a tool's screenshot) or `[Image #N]` (an image you pasted), the placeholder is now highlighted. Hover it for a thumbnail, click it for the full view. Each placeholder is checked against the tool named on the call line above it, so a row is never given another step's image. If the screen and the record don't line up, for example where Claude Code folded the output away, the row is simply left unmarked.
- **Show where it appeared.** The full-size viewer has a button that closes it and scrolls the terminal to the row the image was shown on, with the call that made it just above and the row briefly highlighted. The button is greyed out once that row has left the scrollback.
- **What led to it.** Thumbnails and the viewer now say what the tool was pointed at (an element, a file, a URL), the page the browser was on for a browser screenshot, and the last thing Claude said before taking it. A pasted image shows the words you sent with it. All of this comes from the session's own record, so it is there even when the terminal row is long gone.

## Smaller things

- **New screenshot preview.** While the image strip is closed, a new screenshot appears briefly in the corner of the terminal. Several in a row show as one preview with a count. Click it to open the image. It stays while the pointer is on it. Images you pasted yourself are not announced.
- **Copy image.** The viewer can put the image on the clipboard, ready to paste into another app or another session.
- **Ctrl+↑ / Ctrl+↓ between your prompts.** In a Claude session, jump to the previous or next prompt you sent. The landing row is briefly highlighted. Going past the last prompt returns to the bottom. Claude Code's own input box is never a stop, and the keys are never sent to the agent.

## Under the hood

- A new automated check (`qa:image-rows`) drives a fixture screen drawn the way Claude Code draws it. It covers marking and opening image rows, the viewer's context and "show in terminal", copying, the arrival preview and prompt jumps. It runs on every change on Windows.
- The terminal now enables xterm's marker and decoration API. Image rows are re-paired at most every 2.5 seconds, and only for the selected session when it has images; the performance gate is unchanged (no idle animation or DOM churn, no main-process stall while streaming).

The context lines need 1.40.0 on the PC running the session. With an older host the strip and viewer keep working without them.

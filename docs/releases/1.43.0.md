# DevDeck 1.43.0

## Parallel sessions in separate workspaces

Running two agents on one project used to mean two agents editing the same files. A session can now start in a **separate workspace**: its own folder and git branch, so it never touches what the project's other sessions are doing.

- **Start one:** use the branch button in a session's header. DevDeck creates a git worktree from the project's current commit and opens a new session in it.
  - The worktree lives in `.claude/worktrees/<name>`, the same place Claude Code's own `--worktree` uses.
  - Its branch is `devdeck/<name>`.
- **See what it has done:** its header shows how many files it has changed and how many commits it has made.
- **Keep the project's status clean:** the workspace folders are listed in the repository's local `.git/info/exclude`, so they never show up as changes in the project.
- **Clean up:** the bin button in a workspace session's header closes the session and removes the folder and its branch.
  - It first says what would be lost, and mentions only what is actually there: uncommitted changes, or commits the starting branch does not have.
  - If there is unmerged work, it suggests asking a session on the starting branch to merge it first.
  - Nothing is deleted without that confirmation.
- **On another PC:** this works for sessions on another PC as well. Creating or removing a workspace there needs the same permission as starting a session. A PC still on an older DevDeck says it needs updating.

The What's new window lists this, with Show me, and the button carries a NEW dot until you first use it.

## Under the hood

- **Folder permissions:** a project registered as a single folder admits its own workspaces, `<repo>/.claude/worktrees/<name>`, exactly one level down. Nothing else inside the repository is admitted.
- **What can be removed:** only a folder DevDeck created as a workspace, on a branch it named.
- **Windows folder leftovers:** git can drop a workspace from its list while Windows still holds the folder for a moment. DevDeck then finishes removing that one folder itself.
- **Tests:**
  - New tests run against real temporary git repositories: creating, counting changes, refusing to drop unmerged work, and cleaning up after a half-removed workspace.
  - `qa:cockpit-tools` creates a workspace from the header, sees its change counted, and cleans it up through the warning.

# DevDeck 1.42.0

## See what changed

- **What's new, once after each update.** A window lists what is new since the version you last ran, with where each feature is and a **Show me** button. Show me takes you there and rings the button or setting. It does not open on a first install. Settings → About → **What's new** opens it again at any time, listing everything since 1.39.0.
- **NEW dots.** New buttons carry a small orange dot until you first use them:
  - quick replies, the timeline and the image strip in a session's header
  - Mark up in the image viewer
  - 📎 for a session on another PC
  - the new setting below

## Claude tells DevDeck what it is doing (experimental)

DevDeck has always guessed a session's state by reading its screen: the spinner, the prompt, how long since the last output. Claude Code 2.1.295 and later can report its own state to a terminal that asks for it, and DevDeck now asks.

- The session header shows what Claude reports:
  - **Working**, with a percentage when it knows one
  - **Needs your approval**, **Asking you a question** or **Needs sign-in**, in amber
  - **Done**, with a line on what it just did
  - **Stopped on an error**
- The sidebar and tray use the same report, so "needs you" no longer depends on how the screen happens to look.
- The Windows notification says why the session is waiting, for example "Claude is waiting for your approval".

**On Windows this is off until you turn it on:** Settings → **Claude status signal (experimental)**.

- **Why it is opt-in:** Windows' own console layer (ConPTY) answers the question Claude Code asks and drops DevDeck's reply, so the report never arrives. With the setting on, new sessions run on the newer ConPTY that ships with DevDeck, the one Windows Terminal uses.
- **When it applies:** sessions started after you turn it on.
- **If something looks wrong:** turn it off and restart the session.

On macOS and Linux there is no console layer in between, so the report is always used.

## Under the hood

- **Checked against the real Claude Code 2.1.306:**
  - the probe is answered once, by DevDeck itself, before any window sees the output
  - the states went idle → working → done, with a line on what it did
  - with Windows' own ConPTY the reply never reaches the program, and with the bundled one it does
- **Bundled ConPTY in the installer:** if its files are missing, sessions fall back to Windows' own ConPTY and the status signal is simply not used.
- **Fixed before release:** the wrapper that closes a session's whole process tree was hiding which ConPTY a session ran on.
- **New automated checks (`qa:cockpit-tools`):**
  - What's new and Show me
  - the NEW dots
  - the status in the header: working, needs approval, done
  - quick replies, the timeline and markup, all on the bundled ConPTY
- **Packaged-build check:** the release workflow now runs `qa:cockpit-tools` against the packaged Windows app as well.

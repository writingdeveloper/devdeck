# DevDeck 1.45.0

## Send any file to a session on another PC

Before, a session on a paired PC took images and 21 kinds of documents (text, data, logs, PDF) up to 5 MB each. A zip, a spreadsheet, a source file or a video was refused.

- **Any kind:** zip, xlsx, docx, source files, audio, video, binaries.
- **Up to 4 GB per file:** large files are sent in 2 MB pieces. A file over 8 MB shows its progress while it goes.
- **Drop it or use 📎:** both work on a remote session. The 📎 picker no longer filters by kind. The path where the file landed on the other PC is typed into the session, as before.
- **Images:** they still go as PNG, so the agent can look at them. An image too large to redraw as PNG within 5 MB now goes as it is, instead of being refused.
- **The other PC needs 1.45.0.** An older DevDeck there still takes what it did before (the 21 document kinds, up to 5 MB), and DevDeck says when something was skipped for that reason.

## What is still checked, on the PC receiving the file

Sending a file needs the same permission as typing into its sessions. A device that can type into a session can already have the agent there run anything, so checking the file's kind only got in the way. What is kept:

- **Where it goes:** the file is written only into the temp folder, under a name DevDeck chooses. It is never written to a path the sender picks. DevDeck removes it after a day.
- **Never opened:** DevDeck does not open or run a received file.
- **Marked as downloaded:** on Windows the file is marked as coming from the internet (Mark of the Web), so opening it from Explorer shows the usual warning first.
- **Disk space:** a file is refused if writing it would leave less than 2 GB free on that disk.
- **Limits:** at most 4 uploads are open at once. An upload with nothing new for 5 minutes is dropped and its partial file is deleted.

## Under the hood

- **New methods:** `cockpit:uploadStart`, `uploadChunk`, `uploadFinish` and `uploadAbort`, with the `control` permission. `cockpit:receiveFile` is kept for senders older than 1.45.0.
- **Tests:**
  - On the receiving side, pieces are written in order. A piece that is out of order, too large or past the announced size is refused. A file with bytes missing never lands under its name. The size, disk-space and open-upload limits hold, and the Windows Mark of the Web is written.
  - On the sending side, a file is split and reported in order. An empty file is sent. A refused piece abandons the upload. An older PC is told apart from a full disk.
  - `qa:images-remote` sends a 9 MB binary between two real paired DevDecks and checks that it arrives byte for byte, with its progress shown.

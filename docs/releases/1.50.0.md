# DevDeck 1.50.0

## A tile that is off screen no longer asks the document whether it is

1.49.1 stopped hidden terminals from drawing. Measuring that build with 20 sessions all scrolling at once showed what was left: the check itself.

- **Measured** (1.49.1, 20 tiles each printing ten lines a second, styled like an agent's output): 13 frames over 50 ms and eleven long tasks of 50 to 66 ms in under two seconds, the longest frame 91 ms. The profile: 333 ms of 1,731 in `checkVisibility`, 108 ms in `getClientRects`.
- **Cause.** Before every draw, each tile asked the document "am I displayed?". That question is not free — the document brings its styles up to date before answering — and nineteen hidden tiles asked it in the middle of a frame in which the visible one had just rewritten its rows. Separately, the session list from before the sidebar redesign, which a stylesheet rule keeps permanently hidden, was asked for its boxes on every list render (every activity change of every session), which lays out the whole document.
- **Fix.** A tile that is not the selected one knows it from its own class, with no question put to the document; the selected tile asks whether the terminal pane is displayed at most once per task (`tileDrawn`, `oncePerTask` in `src/renderer/hiddenTerminal.ts`). The hidden list's `display` is read once.
- **After**, same workload: no frame over 50 ms, no long task, longest frame 49 ms. Switching sessions on a quiet deck of 20 takes 10 to 30 ms from click to painted.

The performance gate counts these questions now (`hidden: layout questions asked on behalf of what is not on screen`, limit 0; 1.49.1 scores 34 with two tiles).

## Electron 45

Electron 44.10.0 → 45.3.1 (Chromium 156, Node.js 24.22). Checked against its breaking changes: the preload imports nothing but `electron`, no 32-bit build is published, and none of the removed or changed APIs (`contentTracing` heap profiling, desktop capture source ids, `requestStorageAccessFor`, ASAR file descriptors) are used.

- **One deprecation to act on before Electron 46**: the synchronous `safeStorage` calls that protect a PC's DevDeck Link identity (`src/main/link/identity.ts`) are deprecated in 45 and removed in 46. They still work here and are left as they are in this release — that file holds the key two paired PCs recognise each other by, and it will be moved to the asynchronous API as a change of its own.

Also: electron-builder 26.18.0, electron-updater 6.8.11, vitest 5.1.0.

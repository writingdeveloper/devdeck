# DevDeck 1.39.0

Includes 1.38.1, which was tagged but not published separately.

## See what a session looked at

- **Image strip.** The 🖼 button in a Claude session's header shows the screenshots its tools took (Playwright, Windows MCP, Blender and others), the images you pasted, and the image files it wrote — newest first, between the header and the terminal. Click one for a full-size view: ←/→ step through them, Esc closes, Save keeps a copy. Images that arrived while the strip was closed show as **+N** on the button.
- It reads the session's own transcript, where those screenshots exist and nowhere else, and only what was added since the last look (a 133 MB transcript: 100 ms the first time, about 1 ms after).
- Works for a session on another PC: thumbnails are made on that PC, so a 4K screenshot crosses the connection as a ~30 KB preview.
- Clicking an image path in a remote session's terminal now shows the image instead of "that file is on another PC".

## Attach files

- **📎** in the session header, or drag files onto the terminal. On this PC the file's own path is typed into the prompt.
- For a session on another PC, images (PNG, JPEG, GIF, WebP, BMP) are sent there as PNG — scaled down if needed — and the path on that PC is typed. Anything that could not be attached is reported.

## Claude Code updates on Windows

- On Windows, Claude Code cannot update itself while any session is running it, so with several sessions open its background update keeps failing. When a session shows "Auto-update failed", or "Update installed" while other sessions are open, the header offers **Update all (N)**: it waits for running turns (and permission prompts) to finish, stops every Claude session on this PC, runs `claude update`, and reopens each conversation. Sessions are saved first, so quitting DevDeck in the middle loses nothing.

## Fewer freezes when sessions come back

- Restored sessions now start one at a time, each after the previous one has finished starting. Before, a reboot, an update or **Restore all** started every agent at once. One `claude --resume` of a large conversation was measured at 1.6 GB and ~10 CPU-seconds while starting, four at once at 6.6 GB and 88 CPU-seconds within five seconds — enough to stall a PC for minutes.

## Usage footer

- No more daily "Login expired". Claude's access token lasts about eight hours and is renewed by Claude Code on its next reply; while the 30-day refresh token is still valid the footer now says **Awaiting refresh** and keeps the last numbers, with no sign-in prompt. Sign-in is offered only when the refresh token is gone or rejected. *(1.38.1)*

## Security

- A paired device with only "observe" permission can read just the images a session's own record lists. Image files are checked by their contents, must really be inside a project folder (symlinks and junctions are resolved), and full-size images are kept small enough that they can never drop the connection.

## Under the hood

- New automated checks run on every change: a performance gate (no animation or DOM churn on an idle deck, no main-process stalls while streaming — each limit verified by injecting the regression it guards against), the image strip locally and across two paired PCs, attach, Update all, and staggered restores.
- TypeScript 7, Vitest 5, Playwright 1.64; `@types/node` now matches Electron's Node 24.

The image strip, attach and remote image viewing need 1.39.0 on the PC running the session; with an older host the strip stays empty and remote image paths keep the old message.

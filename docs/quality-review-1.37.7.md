# PC 전환 진행 표시와 터미널 상단 확인

## 확인 및 개선

| 항목 | 확인한 원인 | 처리 |
| --- | --- | --- |
| PC 전환이 멈춘 것처럼 보임 | 프로젝트 요청은 최대 150초를 기다리지만 회색 자리 표시자만 표시 | 상단 고정 도구 모음에 대상 PC 이름과 회전 표시. 8초 후 지연 안내. 전환 조작은 계속 허용 |
| 전환을 반복할 때 진행 상태 혼동 | 이전 요청의 완료가 현재 요청보다 늦을 수 있음 | 선택 세대와 요청 번호가 현재일 때만 상태를 종료. 실패·재시도에도 같은 규칙 적용 |
| 터미널 이전 출력이 일찍 사라짐 | xterm 기본 보관량 1,000줄 사용 | 세션당 최대 10,000줄 보관 |
| 접속·화면 복구 시 첫 출력 줄 누락 | 보관 상한에 도달하지 않은 출력도 첫 줄을 무조건 제거 | 실제 앞부분이 잘린 버퍼에만 경계 복구 적용. 온전한 첫 줄과 커서 제어 문자 보존 |

4개 언어와 화면 읽기 프로그램용 진행 상태를 적용했다. 로딩 표시를 위해 진행률을 추정하거나 중복 요청을 보내지 않는다. 데이터 스캔 및 네트워크 대기 시간 자체를 단축하는 변경은 아니다.

## QA

로컬 전체 단위 검사: 1,257개 통과, 기존 1개 생략. 로컬 Electron 복원력 검사: 9개 시나리오 통과.

- 기존 저장 실패·초안 보존·재시작·응답 역전 검사 유지.
- 원격 응답을 보류하고 즉시 로딩 문구, 8초 후 지연 문구, A→B→A 전환 중 이전 실패 무시 확인.
- 원격 실패 후 로딩 종료, 재시도 시 로딩 재개, 성공 시 종료 확인.
- Windows 네이티브 터미널에 1,500줄 출력 후 검색으로 최초 출력에 접근.
- 스크롤한 설정 화면에서 터미널로 이동하고 800×600, 1280×800 창 크기에서 제목·터미널의 상단 및 하단 경계 검사.
- 터미널 버퍼 단위 검사에 온전한 첫 줄, 잘린 이스케이프 접두부, 줄바꿈 없는 화면 갱신, 크기 변경 후 첫 줄 보존 추가.
- 첫 Link 검사는 연결·표시·입력·화면 크기 협상에 성공했지만 호스트 종료 단계에서 멈췄다. 네이티브 종료 콜백이 반환된 다음 이벤트 루프 차례에 앱을 종료하도록 보완했다. QA 종료 대기도 30초로 제한하고, 대기 초과 시 해당 검사 프로세스를 종료한 뒤 실패로 기록한다.
- 보완 후 Link 전체 검사는 호스트 재시작, 재연결, 복원 중복 방지까지 통과했고 호스트·뷰어가 모두 종료 코드 0으로 종료했다.

## 구분해야 하는 제한

제목이나 버튼이 화면 위로 잘리는 현상은 이번 탐색과 경계 검사에서는 재현하지 못했다. 출력 기록의 누락과 같은 문제로 단정하지 않았다.

10,000줄은 실행 중인 화면의 보관 상한이다. 원격 연결 시 받는 출력은 256 KiB로 제한되며 크기 변경 때 화면 왜곡을 막기 위해 이전 크기의 원시 출력을 폐기한다. 재연결·수동 화면 복구는 최근 출력으로 화면을 다시 만들기 때문에 모든 과거 기록을 보장하지 않는다. 이를 보장하려면 화면 복구용 데이터와 영구 대화 기록을 분리하는 후속 설계가 필요하다. 기존에 폐기된 출력은 이번 변경으로 복구되지 않는다.
